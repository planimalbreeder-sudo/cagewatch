# 케이지워치 v1

사용하지 않는 안드로이드 폰을 케이지 위에 거치해, 햄스터의 움직임을 기록하고 장시간 움직임이 없을 때 알람을 울리는 웹앱입니다. 설치할 앱도, 서버도, 계정도 필요 없습니다.

```
카메라 → 프레임 차분(움직임 점수) → 1분 단위 집계 → IndexedDB
                                            ↓
                              무활동 N분 지속 → 소리/알림 경보
```

---

## 먼저 읽을 것 — 하드웨어 주의사항

**이건 보조 수단입니다. 의료기기도, 생명 유지 장치도 아닙니다.** 폰이 멈추거나 와이파이가 끊기거나 햄스터가 은신처 안에서 안 보일 수 있습니다.

1. **발열과 배터리 팽창** — 카메라를 24시간 켜고 상시 충전하면 폰이 상당히 뜨거워집니다. 리튬 배터리는 고온 + 100% 유지 상태에서 팽창합니다. 통풍이 되게 거치하고, 가능하면 충전 제한(80%) 기능을 켜세요. **케이지 안이나 베딩 위가 아니라 케이지 밖 위쪽에** 두세요.
2. **낙하** — 햄스터가 폰을 떨어뜨릴 수 없는 구조로 단단히 고정하세요. 폰이 케이지 안으로 떨어지면 압사 위험이 있습니다.
3. **야간 촬영** — 햄스터는 야행성인데 폰 카메라는 어둠에서 아무것도 못 봅니다. 적외선 필터가 박혀 있어 IR 램프도 소용없습니다. **희미한 적색 LED 상시 조명**이 현실적인 해법입니다. 햄스터는 적색광을 거의 인지하지 못해 수면 방해가 적습니다.
4. **은신처** — 햄스터가 하우스 안에 들어가 있으면 움직여도 카메라에 안 잡힙니다. 무활동 알람 오탐의 가장 큰 원인입니다. 카메라 각도를 하우스 출입구와 쳇바퀴, 먹이통이 보이게 잡으세요.

## 1. 호스팅 (카메라를 쓰려면 HTTPS가 필요합니다)

브라우저는 **HTTPS 또는 localhost**에서만 카메라를 허용합니다. `file://`로 열면 카메라가 안 열립니다. 둘 중 하나를 고르세요.

### 방법 A — GitHub Pages (상시 운용 권장, 약 10분)

1. github.com에서 새 저장소를 만듭니다 (public).
2. 이 폴더의 파일 5개를 업로드합니다: `index.html`, `app.js`, `sw.js`, `manifest.webmanifest`, `icon.svg`
3. Settings → Pages → Source를 `main` 브랜치 `/ (root)`로 지정하고 저장합니다.
4. 1~2분 뒤 `https://<사용자명>.github.io/<저장소명>/` 로 접속됩니다.

PC를 꺼도 되고 URL이 영구적이라 장기 운용에 가장 적합합니다.

### 방법 B — PC에서 임시 서버 + Chrome 플래그 (빠른 테스트, 약 3분)

PC에서:

```bash
cd /c/Users/yangs/.claude/sessions/petwatch && python -m http.server 8000
```

PC의 LAN IP를 확인하고(`ipconfig`), 폰 Chrome에서:

1. `chrome://flags/#unsafely-treat-insecure-origin-as-secure` 접속
2. 입력란에 `http://192.168.0.10:8000` 처럼 **PC의 실제 IP와 포트**를 넣고 Enabled로 변경
3. Chrome 재시작 후 그 주소로 접속

PC가 켜져 있어야 하므로 테스트용으로만 쓰세요.

## 2. 폰 설정

1. 폰 Chrome으로 위 주소를 엽니다.
2. 메뉴 → **홈 화면에 추가** → 홈에서 실행하면 주소창 없는 전체화면으로 뜹니다.
3. 안드로이드 설정에서 이것들을 조정하세요:
   - **설정 → 디스플레이 → 화면 자동 꺼짐: 사용 안 함** (앱이 Wake Lock을 걸지만 이중으로 막아두는 게 안전합니다)
   - **설정 → 배터리 → 절전 모드 끄기**, Chrome을 배터리 최적화 **제외**
   - 방해 금지 모드 해제 (알람 소리가 막힙니다)
   - 볼륨을 충분히 올리기

## 3. 사용

1. 카메라를 케이지 쪽으로 고정합니다.
2. **관찰영역 지정**을 누르고 케이지 영역만 드래그로 감쌉니다. (바깥의 사람·커튼·TV 반사가 오탐의 주원인이라 이 단계가 중요합니다)
3. **시작**을 누릅니다. 카메라 권한을 허용하세요.
4. 첫 **60초는 자동 보정** 구간입니다. 이 동안 카메라 노이즈 수준을 측정해 "움직임 판정 기준"을 정합니다. 케이지를 건드리지 마세요.
5. 보정이 끝나면 상태가 **감시 중**으로 바뀝니다.

### 기본 설정값

| 항목 | 기본값 | 의미 |
|---|---|---|
| 무활동 알람 기준 | 180분 | 3시간 움직임이 없으면 알람 |
| 감시 시간대 | 20:00 ~ 08:00 | 이 시간대 밖에서는 무활동을 문제로 보지 않음 |
| 샘플링 간격 | 250ms | 초당 4회 비교 |
| 픽셀 변화 임계값 | 30 | 이만큼 밝기가 바뀐 픽셀을 "변했다"고 판정 |
| 움직임 판정 배수 | 4 | 노이즈 수준의 4배를 넘으면 실제 움직임 |
| 분 활동 인정 기준 | 2% | 1분 중 이 비율 이상 움직여야 "활동한 분" |
| 보관 기간 | 30일 | 이후 분 단위 기록 자동 삭제 |

**분 활동 인정 기준**도 중요합니다. 무활동 알람은 개별 프레임이 아니라 **분 단위**로만 판정합니다. 노이즈 바닥이 판정 기준에 가까우면 분당 한두 프레임은 우연히 기준을 넘는데, 그걸 활동으로 치면 동물이 실제로 움직이지 않아도 무활동 시간이 영영 쌓이지 않아 **알람이 울리지 않습니다**. 오탐보다 위험한 미탐이라 분 단위로 올렸습니다. 모니터 탭의 "마지막 움직임"도 이 분 단위 값을 그대로 보여주므로, 화면에 보이는 값이 곧 알람 시계입니다.

**감시 시간대**가 핵심입니다. 햄스터는 낮에 몇 시간씩 자므로 이 제한이 없으면 낮잠마다 알람이 울립니다.

## 4. 인형으로 먼저 검증하기 (권장)

햄스터를 넣기 전에 비슷한 크기의 인형으로 돌려보는 게 좋습니다. 다만 **인형으로 검증되는 것과 안 되는 것**을 구분하세요.

### 인형으로 검증 가능

**① 보정 숫자부터 본다 — 가장 중요**

보정이 끝나면 이벤트에 `보정 완료 (노이즈 N, 기준 M)` 이 찍힙니다. 이 둘이 전부입니다.

| 노이즈 N | 판정 | 조치 |
|---|---|---|
| 100 미만 | 좋음 | 그대로 진행 |
| 100~300 | 애매 | 관찰영역을 더 좁게, 조명 보강 |
| 300 이상 | 나쁨 | 픽셀 변화 임계값을 35~45로 올리고 재보정 |

노이즈가 높으면 판정 기준도 같이 올라갑니다. 기준이 300을 넘으면 햄스터의 작은 움직임(50~200픽셀)을 구조적으로 못 잡습니다. 실측 예: 노트북 웹캠 저녁 실내광에서 픽셀 임계값 18이면 **노이즈 634 / 기준 1306 (사실상 먹통)**, 30으로 올리면 **노이즈 47 / 기준 83 (정상)**.

**② 민감도 — 얼마나 작은 움직임까지 잡히나**

감시를 시작하고 보정이 끝난 뒤, 인형을 단계별로 움직이며 모니터 탭의 "현재 움직임" 숫자를 봅니다.

| 동작 | 기대값 |
|---|---|
| 가만히 둠 | 판정 기준보다 **한참 아래** |
| 수염 떨 듯 1cm 꼼지락 | 기준 근처 |
| 한 걸음(3~5cm) 이동 | 기준의 2배 이상 |
| 케이지 가로지르기 | 기준의 5배 이상 |

"한 걸음"이 기준을 못 넘으면 **움직임 판정 배수**를 내리고, 가만히 둔 상태에서 기준을 넘으면 올리세요. 바꿨으면 **재보정**.

**③ 오탐 — 아무것도 없을 때 정말 0인가**

인형을 그대로 두고 **30분 방치**한 뒤 기록 탭을 봅니다. 활동률이 **0~2%**면 정상입니다. 계속 10% 이상 나오면 노이즈나 외부 조명이 영역에 들어오는 것이니 픽셀 변화 임계값을 올리거나 관찰영역을 좁히세요.

**④ 알람 — 정말 울리나**

180분을 기다릴 수 없으니 임시로 낮춰서 확인합니다.

1. 설정 → 무활동 알람 기준을 **5분**으로, 감시 시간대 제한을 **끄기** → 저장
2. 인형을 건드리지 않고 5분 대기
3. 빨간 배너 + 소리 + 알림이 뜨는지 확인
4. 인형을 움직이면 알람이 자동으로 풀리는지 확인
5. **확인 끝나면 180분과 감시 시간대를 반드시 원복**

### 인형으로 검증 안 되는 것

- **야간 적색조명에서의 감지** — 조명을 실제 운용 조건으로 맞춘 뒤 밤에 다시 ①을 해야 합니다. 밝은 낮에 맞춘 임계값은 어두운 밤에 그대로 쓰면 거의 아무것도 못 잡습니다.
- **은신처에 숨었을 때** — 실제 햄스터는 하우스 안에 들어갑니다. 인형은 안 들어갑니다. 오탐의 가장 큰 원인인데 인형으로는 재현이 안 됩니다.
- **쳇바퀴** — 돌아가는 쳇바퀴는 움직임 점수가 매우 크게 나옵니다. 실제로 돌려봐야 압니다.
- **장시간 안정성** — 발열, 자동노출 드리프트, 브라우저 중단은 며칠 돌려야 드러납니다.

그래서 순서는 **인형으로 ①②③④ → 햄스터 투입 → 밤에 ① 재확인 → 2~3일 방치 후 차트 검토**입니다.

## 5. 오탐 튜닝 (2~3일 돌려본 뒤)

**기록** 탭의 24시간 차트를 보고 판단하세요.

| 증상 | 조치 |
|---|---|
| 아무도 없는데 활동률이 계속 10~30% | 픽셀 변화 임계값을 35~45로 올리거나, 관찰영역을 더 좁게 |
| 밤에도 활동률이 거의 0 | 조명이 부족합니다. 적색 LED를 더 밝게. 또는 판정 배수를 2~3으로 내리기 |
| 특정 시각에만 활동률이 치솟음 | 그 시각의 외부 조명 변화(해 뜸, 거실 불)가 영역에 들어옵니다. 영역 조정 |
| 낮에 알람이 울림 | 감시 시간대를 좁히거나 무활동 기준을 늘리기 |
| 쳇바퀴만 돌 때 안 잡힘 | 쳇바퀴가 영역에 들어오게 각도 조정, 판정 배수 내리기 |

튜닝은 **한 번에 하나씩** 바꾸고 하루 돌려보세요. 설정을 바꾼 뒤에는 **재보정**을 누르세요.

차트 모양이 밤에 솟고 낮에 가라앉는 형태로 나오면 감지가 제대로 되고 있다는 신호입니다. 하루 종일 평평하면 뭔가 잘못됐습니다.

## 6. 데이터

**기록 → CSV 내보내기**로 분 단위 원본을 받을 수 있습니다.

```
datetime, epoch_min, frames, active, invalid, active_ratio, score_sum, score_max
```

- `frames` — 그 1분간 유효하게 비교한 프레임 수
- `active` — 그중 움직임으로 판정된 프레임 수
- `invalid` — 조명/장면이 급변해서 버린 프레임 수 (이 값이 크면 환경이 불안정)
- `active_ratio` — `active / frames`, 그 분의 활동률

v1은 이 중 "무활동 지속"만 보지만, 저장은 전부 하고 있습니다. 나중에 시간대별 기준선이나 일주기 패턴 변화 탐지를 붙일 때 과거 데이터를 그대로 소급 분석할 수 있습니다.

> 데이터는 폰 브라우저의 IndexedDB에만 있습니다. 브라우저 데이터를 지우면 함께 사라집니다. 중요하면 주기적으로 CSV를 내보내세요.

## 7. 알고 있는 한계

- **포그라운드 전용** — 화면을 켠 채 앱이 떠 있어야 합니다. 안드로이드가 탭을 중단하면 프레임이 멈추고, 60초 이상 멈추면 "감시가 멈췄습니다" 경보가 울립니다.
- **원격 알림 없음** — v1은 케이지 폰에서만 울립니다. 외출 중에는 들을 수 없습니다. (v3에서 ntfy/텔레그램 예정)
- **2D 움직임만** — 카메라 쪽으로 다가오거나 멀어지는 움직임은 약하게 잡힙니다.
- **적색 야간조명에서 감도 저하** — 분석은 RGB를 BT.601 휘도로 접은 흑백으로 하는데, 이 공식은 빨강에 30% 가중치만 줍니다. 화면이 적색 단색이 되는 야간조명에서는 신호가 약해집니다. 적색 채널만 쓰는 야간 모드가 필요하며 아직 없습니다.
- **개체 구분 없음** — 합사 중이면 둘의 움직임이 합산됩니다.
- **은신처 안은 못 봅니다** — 위 주의사항 4번 참고.

| 폰 후면 카메라, 실내광 | 노이즈 0 / 기준 6 | 매우 깨끗 |
| 폰, **불 끈 방** | 노이즈 0 / 기준 6 | **아무것도 안 보임** |
| 폰, **화면 적색 조명(전면 카메라)** | — | **코앞 몇 cm만 감지** |

어두운 방에서 노이즈 0이 나오는 것은 깨끗해서가 아니라 화면이 새까매서다.
손을 흔들어도 반응이 없었다. 이 둘은 숫자만으로 구분할 수 없어서,
v1.4부터 평균 밝기가 12 미만이면 경고하도록 했다.

화면 조명은 밝기가 턱없이 부족하다. 적색 세기를 100%로 올려도 수십 cm를 못 간다.
**야행성 동물을 감시하려면 외부 적색 LED가 사실상 필수다.**
햄스터는 야행성이므로, 낮에만 감시하면 자는 시간만 보게 된다는 점에 유의.

### 다음에 시도할 것
- USB 적색 LED 조명(5천원대)을 케이지 위에 설치 후 재보정
- 그 조건에서 설정의 **적색 채널로 분석**을 켜고 노이즈/기준 측정
- 밝기가 12를 넘고 손 흔들기가 잡히면 야간 감시 가능
